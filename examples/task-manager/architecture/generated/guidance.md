## Logical modules

- **Clients** (`module:clients`): The web app, mobile app and command-line tool people use. They show tasks and ask other modules to change them.
- **Tasks** (`module:tasks`): Owns task state, its shape, recurrence and the task-changed event every other module reacts to.
- **Reminders** (`module:reminders`): Schedules and fires reminders and handles snoozing.
- **Offline sync** (`module:sync`): Keeps offline devices in step without losing their edits.
- **Notifications** (`module:notifications`): Delivers push and email notifications.
- **Search** (`module:search`): Keeps a searchable copy of tasks.

## Open questions

- `decision:conflict-resolution`: Open: the last write wins, or edits are merged field by field. Merging keeps more work but makes the change-set format and the sync engine more complex.
- `decision:offline-reminders`: Open: schedule reminders on the device as well as the server, or accept that an offline phone misses them until it reconnects.
- `decision:recurrence-model`: Open: one record whose due time moves forward on completion, or one record per occurrence. This changes the task shape, history and how reminders are scheduled.
- `relationship:conflict-change-set`: Merging may require per-field base versions in each change.
- `relationship:conflict-sync`: Field-level merging needs per-field versions in the sync engine.
- `relationship:offline-reminders-mobile`: The mobile app may need to schedule local reminders.
- `relationship:offline-reminders-scheduler`: Device-side scheduling would split reminder logic across server and phone.
- `relationship:recurrence-model-rules`: Determines whether rules move a due time forward or create new tasks.
- `relationship:recurrence-model-task`: One record or one per occurrence changes the task shape.
