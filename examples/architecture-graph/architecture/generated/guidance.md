## Find the relevant design

Use the project's installed `ag context --id <id>` or `ag context --file <path>`. You can also use `--module <id>`, `--guardrail <id>`, or `--query <text>`. Results include incoming and outgoing relationships. Read the referenced files and keep open questions visible.

Context is limited to 60 nodes and 120 examined relationships by default. A shortened result explicitly says it is incomplete. Narrow the lookup or raise `--max-nodes` and `--max-relationships` when needed. This briefing is an overview, not the full architecture.

## Logical modules

- **Declarations and validity** (`module:declarations`): Owns authored meaning, project loading and structural checks. Exposes validated project snapshots, format/module contracts and file/proof boundaries.
- **Indexes and focused context** (`module:context`): Owns disposable lookup indexes and bounded retrieval. Imports validated project snapshots; exports context capability and index construction for loading/generation.
- **Public interfaces and guidance** (`module:interfaces`): Owns CLI/library entrypoints and generated guidance/drift. Coordinates declarations, context and installation without redefining their semantics.
- **Agent adoption and distribution** (`module:delivery`): Owns shared skill installation, build/package delivery and adoption decisions. Imports public operations, schema authority, maintenance capabilities and project boundaries.
